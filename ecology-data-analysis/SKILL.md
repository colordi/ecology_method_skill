# 生态学数据分析

## 概述

本 skill 通过三阶段工作流程指导用户进行生态学数据分析，生成包含 R 代码、统计结果和生态学解释的专业 Quarto 报告。

## 工作流程

分析遵循三个连续阶段：

1. **意图对齐**：通过针对性问题识别研究问题和数据特征
2. **结构冻结**：创建详细的 Quarto 格式分析大纲
3. **渐进式分析**：执行分析并将结果填入报告

### 中文字体配置

**重要**：为确保生成的图表和PDF中中文字符正确显示，本 skill 使用 `showtext` 包加载系统字体。

**配置说明**：
- 使用 `showtext` 包自动检测操作系统并加载相应的系统字体
- macOS：使用 `/System/Library/Fonts/Supplemental/Songti.ttc`
- Windows：使用 `C:/Windows/Fonts/simsun.ttc`
- Linux：使用 `/usr/share/fonts/truetype/wqy/wqy-microhei.ttc`
- 模板文件已预配置字体支持，确保跨平台兼容性
- 所有生成的 ggplot2 图表将自动使用该字体渲染中文

**在生成代码时的注意事项**：
- 确保在 setup 代码块中包含 `library(showtext)` 和字体配置
- 使用操作系统检测代码自动选择字体路径
- 调用 `showtext_auto()` 启用自动渲染
- 在 ggplot2 主题中设置 `base_family = "cjk"`
- 在 knitr 选项中设置 `fig.showtext = TRUE`
- **必须遵循** `references/RENDERING_GUIDE.md` 中的字体配置规范

### 阶段 1：意图对齐

**目标**：通过高信息密度的问题快速理解用户的数据和研究目标。

**流程**：
1. 阅读 `references/intent-questions.md` 获取提问框架
2. 针对以下方面提出问题：
   - 数据类型和结构
   - 研究设计
   - 研究目标
   - 变量及其测量尺度
3. 使用 `references/analysis-methods.md` 识别合适的分析方法

### 阶段 2：结构冻结

**目标**：创建全面的分析大纲以避免上下文长度限制。

**流程**：
1. 复制 `assets/analysis_report_template.qmd` 作为起点
2. **参考** `references/RENDERING_GUIDE.md` 了解表格、图表和字体的规范要求
3. 根据阶段 1 的发现定制模板：
   - 更新标题、作者和数据来源信息
   - 添加阶段 1 中识别的具体分析方法章节
   - 每个分析章节应包含：方法说明、代码块、结果和解释占位符
4. 将定制的大纲保存为用户工作目录中的 .qmd 文件

### 阶段 3：渐进式分析

**目标**：逐步执行分析并将结果填入 Quarto 报告。

**受众定位**：报告的主要受众是**非技术背景的领导和决策者**，因此内容应注重可读性和可理解性。

**关键原则**：
- 边分析边填充，每完成一个章节后与用户讨论并确认，再进行下一步
- **文本为主，代码为辅**：优先撰写详细的文字说明，代码作为支撑材料默认隐藏
- **通俗易懂**：避免过度使用技术术语，必要时提供通俗解释

**流程**：
1. **开始前必读**：仔细阅读 `references/RENDERING_GUIDE.md`，了解表格、图表、字体配置的规范要求
2. 按顺序处理大纲中的每个分析章节
3. 对于每个分析章节：
   - 使用 tidyverse 编写数据处理的 R 代码
   - 使用适当的包（主要是 vegan）执行分析
   - 使用 ggplot2 生成可视化图表（**必须遵循** `references/RENDERING_GUIDE.md` 中的图表样式规范）
   - 生成表格时**必须遵循** `references/RENDERING_GUIDE.md` 中的表格样式规范（禁止使用 `full_width` 或 `scale_down`）
   - 使用 `references/interpretation-guide.md` 解释结果
   - **暂停并与用户讨论**：展示分析结果，询问用户是否满意
   - **填充到 .qmd 文件**：确认无误后，将代码、结果和解释填入相应章节
   - **确认后再继续**：等待用户确认后再进行下一个章节
4. 确保所有结果都包含统计显著性和生态学意义

**内容生成指南**：

每个分析章节应包含以下完整结构（按重要性排序）：

1. **方法背景与定义**（文本为主，约200-300字）
   - 用通俗语言定义该方法是什么，解决什么问题
   - 简要介绍方法的发展历史和在生态学中的应用
   - 用类比或例子帮助非技术人员理解核心思想
   - 示例："方差分析就像比较不同班级的考试成绩，看看班级之间的差异是否超出了学生个体差异的范围"

2. **为什么选择这个方法**（文本为主，约150-200字）
   - 说明该方法如何与研究问题匹配
   - 解释为什么该方法适合当前的数据特征
   - 列出该方法的优势（2-3点）
   - 诚实说明该方法的局限性
   - 示例："我们选择NMDS而不是PCA，因为我们的物种数据不满足线性关系假设"

3. **方法的前提假设**（文本为主，约100-150字）
   - 列出该方法的主要前提假设（2-3个）
   - 用通俗语言解释每个假设的含义
   - 说明如何检验这些假设
   - 报告本研究数据是否满足这些假设
   - 示例："正态性假设要求数据呈钟形分布，我们通过Q-Q图检验，发现数据基本满足该假设"

4. **关键概念解释**（文本为主，约100-150字）
   - 列出并解释该方法涉及的核心术语（3-5个）
   - 避免循环定义，用日常语言解释
   - 说明每个术语的生态学意义
   - 用类比或例子帮助理解
   - 示例："p值就像是'巧合的可能性'，p<0.05意味着这个结果出现的概率小于5%，因此我们认为这不是偶然现象"

5. **分析实施**（代码为主，但需要文字说明）
   - 提供完整的R代码（代码块默认折叠）
   - 在代码块前用文字说明分析步骤（3-5步）
   - 每个步骤用通俗语言描述做了什么
   - 示例："首先，我们将数据按处理组分组；然后，计算每组的平均值和标准差；最后，进行统计检验"

6. **结果展示**（图表为主，配合文字说明）
   - 提供清晰的图表（使用ggplot2，注意配色和标签）
   - 在图表前用文字说明图表展示的内容
   - 详细解释图表的横轴、纵轴、颜色、符号等元素
   - 用文字总结主要发现（2-3点）
   - 示例："图1展示了不同处理组的物种丰富度。横轴表示处理组，纵轴表示物种数量。可以看到，处理组A的物种数量明显高于对照组"

7. **结果解释**（文本为主，约300-400字，这是最重要的部分）
   - **统计学解释**：报告p值、效应量等，用通俗语言解释其含义
   - **生态学解释**：从生态学角度解释结果的生物学意义
   - **与已有研究的比较**：将结果与文献中的发现进行比较
   - **可能的机制**：提出可能的生态学机制来解释观察到的模式
   - **与研究假设的关系**：说明结果是支持还是反对研究假设
   - **不确定性与局限**：诚实讨论结果的不确定性和外推时的注意事项
   - 示例："统计检验显示处理组与对照组存在显著差异(p<0.01)，这意味着这种差异不太可能是偶然产生的。从生态学角度看，这可能是因为处理改善了土壤养分条件，从而支持了更多物种的生存"

**重要提醒**：不要一次性完成所有分析，必须逐章节进行，每个章节都要经过"执行→讨论→填充→确认"的循环。

### references/
- `intent-questions.md`：阶段 1 意图对齐的提问框架

### assets/
- `analysis_report_template.qmd`：预设数据概况、数据清洗和分析方法章节的 Quarto 报告模板
