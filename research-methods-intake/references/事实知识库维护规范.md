# 事实知识库维护规范（循环工作流）

> 目标：让事实核查的“依据”可追溯、可复用、可持续增长。

## 1) 知识库结构

知识库位于 `knowledge-base/`，核心文件：

- `knowledge-base/index.md`：全局索引（主题 → 文件）
- `knowledge-base/search-log.md`：检索日志（可复现）
- `knowledge-base/references.bib`：BibTeX 引用库（可选但推荐）
- `knowledge-base/facts/`：按主题沉淀事实条目
- `knowledge-base/venues/`：按细分领域沉淀期刊/会议条目

## 2) 最小记录集（每条事实必须有）

每条事实条目至少包含：

- 事实陈述（可直接用于“研究方法”写作的句子或要点）
- 适用边界（生态系统/尺度/数据类型/前提条件）
- 证据摘要（为何支持该陈述）
- 引用依据（DOI 或出版方稳定链接，推荐 DOI）
- 可复现线索（检索平台与检索式，或在 `search-log.md` 指向对应条目）

## 3) 循环维护流程（建议节奏）

一次迭代只处理 1–3 条关键“待核查要点”：

1. 从用户材料提取要点 → 写入报告“待核查清单”
2. 设计检索式并记录 → `search-log.md`
3. 筛选与评估来源 → 写出“事实陈述 + 引用”
4. 沉淀到 `facts/` 与 `references.bib`
5. 更新 `index.md`（保证以后能找到）

## 4) 变更可追溯（推荐）

- 在每个主题文件头部追加“变更记录”：日期、变更内容、来源新增/替换原因。
- 若发现此前条目错误或过时：不要静默覆盖，应记录替换依据与新来源。
